## 1. 背景

任务面板的澄清环节现状（`client.js` 第 799–813 行）：

```js
// 待澄清（status === 'clarify'）
<div className="tp-sec" onClick={stopPropagation}>
  <div className="tp-kv"><b>待澄清问题（至少回答一个，其余按未回答处理）</b></div>
  {task.questions.map(q => (
    <div style={{ marginBottom: 8 }}>
      <div className="tp-kv">Q1. {q.q}（{q.why}）</div>
      <textarea className="tp-textarea" rows={2} placeholder="你的回答…" />
    </div>
  ))}
</div>
```

对应样式（`client.js` 第 48、82–84 行）：

| 选择器 | 现状 | 问题 |
| --- | --- | --- |
| `.tp-kv` | `font-size:12px` | 问题正文仅 12px，且与"需求/验收标准"等同级视觉，无区分度 |
| `.tp-sec` | `font-size:12px` | 整块澄清区无边框、无底色，视觉上塌陷进卡片主体 |
| `.tp-textarea` | `font-size:13px` | 作答框与问题同权重，分不清"读的"和"写的" |
| 单问容器 | 内联 `marginBottom:8` | 多个问题时彼此粘连，无"一个问题一张卡片"的边界 |

老板反馈：**澄清的问题文字太小，看不清；希望改成卡片形式、醒目一些。**

同时两处信息缺失：

1. 展开态看不出**答了几问**（提交前无法确认是否漏答）；
2. 收起态的 `cardBadge()`（第 597–606 行）只覆盖 `review / done / develop`，`clarify` 状态**没有徽标**——任务停在"待澄清"时，老板收起卡片就完全看不出有事情等着他做。

---

## 2. 目标

1. 澄清区每个问题渲染为**独立强调色卡片**：有边框、底色、左侧强调竖条、圆角，与卡片内其他文本段落（需求/计划/摘要）在视觉上明确区分。
2. 问题正文放大到 **15px 加粗**，成为该卡片内最醒目的元素；`why` 说明退为次级灰色小字。
3. 展开态显示 **「已答 x/y」** 进度，老板提交前能看到是否漏答。
4. **收起态也显示**待澄清徽章（「待澄清 N 问」），不展开就知道有事要做。
5. 亮/暗主题都成立，沿用现有 CSS 变量与同类卡片的视觉语言（对齐 `.tp-verdict` / `.tp-device-guide`）。
6. 不改动任何 Host 逻辑、数据结构、提交接口与状态机。

## 3. 非目标（明确不做）

- ❌ 不改 `index.js`（Host）任何逻辑：不新增字段、不改 `tasks-action` 的 `clarify-answer` 协议、不改 `pickQuestions`。
- ❌ 不改状态下拉、按钮、徽章以外的卡片既有区域（需求/验收标准/计划/复核报告/截图区不动）。
- ❌ 不做问题折叠（老板已选「每问一张强调色卡片」，未选折叠方案）。
- ❌ 不引入任何第三方依赖或 UI 框架（继续手写 `React.createElement` + 内联 CSS 字符串）。
- ❌ 不做响应式/移动端专门适配（面板是桌面抽屉，沿用现有 `tp-*` 断点约定即可）。
- ❌ 不改 `tasks.json` 落盘结构。

### 5.2 渲染结构

替换 `client.js` 第 799–807 行（待澄清分支）：

```js
(task.questions || []).length > 0 && task.status === "clarify"
  ? React.createElement("div", { className: "tp-clarify", onClick: stop },
      [ React.createElement("div", { className: "tp-clarify-head" }, [
          React.createElement("span", { className: "tp-kv" },
            React.createElement("b", null, "待澄清问题（至少回答一个，其余按未回答处理）")),
          React.createElement("span", { className: cls }, "已答 " + answered + "/" + task.questions.length)
        ]),
        task.questions.map(function (q, i) {
          var done = answeredIds[q.id] === true
          return React.createElement("div", { key: q.id, className: "tp-q" + (done ? " tp-q-done" : "") }, [
            React.createElement("div", { className: "tp-q-head" }, [
              React.createElement("span", { className: "tp-q-no" }, "Q" + (i + 1)),
              React.createElement("span", { className: "tp-q-text" }, q.q)
            ]),
            q.why ? React.createElement("div", { className: "tp-q-why" }, q.why) : null,
            React.createElement("textarea", { className: "tp-textarea", rows: 2, placeholder: "你的回答…", value: ..., onChange: ... })
          ])
        })
      ])
  : null
```

关键点：

- **序号 `Q1`**：由 `q.id.slice(1)` 改为 **索引 `i + 1`**。原实现假设 `id` 形如 `q1`；若 Host 端 id 规则变化会显示错乱，索引是渲染期唯一可靠来源（`pickQuestions` 生成顺序即展示顺序）。
- **`why` 不再拼在问题正文里**（原实现 `q.q + "（" + q.why + "）"`），拆成独立次级行，避免长 why 把问题正文挤成一大坨。
- **已答判定**：见 5.3 的 `clarifyProgress`，与 `submitAnswers()` 的口径**完全一致**（trim 后非空），保证"进度显示已答"⇒"提交时确实会上报"。
- **答案来源**：`answers[q.id] !== undefined ? answers[q.id] : (q.answer || "")`，与现状一致，不改。
- 展开态已回答列表（第 808–813 行，`status !== 'clarify'`）**本次不动**，仍在非澄清状态下展示。

### 5.3 纯逻辑：`clarifyProgress`

在 `client.js` 中新增一个**无副作用纯函数**（放在 `cardBadge` 附近），作为 UI 与测试的共享契约：

```js
// 澄清进度：按提交口径（trim 后非空）统计已答问数，供卡片进度条与已答高亮共用。
// 答案优先级：草稿 answers[qid] > 已有答案 q.answer，与 submitAnswers() 保持一致。
function clarifyProgress(questions, answers) {
  var list = questions || [];
  var drafts = answers || {};
  var answeredIds = {};
  var answered = 0;
  for (var i = 0; i < list.length; i++) {
    var q = list[i] || {};
    var raw = drafts[q.id] !== undefined ? drafts[q.id] : (q.answer || "");
    var text = typeof raw === "string" ? raw.trim() : "";
    if (text) { answered++; answeredIds[q.id] = true; }
  }
  return { answered: answered, total: list.length, answeredIds: answeredIds };
}
```

**测试策略（TDD，两级）**：`client.js` 是 DSH client-modules bundle（`window.__ModuleLoader__.load`），不可直接 `import`。

1. **纯逻辑 + 源码契约**（`test/clarify-card.test.js`）：从源码抽取 `clarifyProgress` 并用 `new Function` 求值后断言行为；CSS 断言精确到「选择器 { 声明 }」整条规则（不用 `includes` 前缀匹配，避免被 `.tp-q-head` 之类顶替而假绿）；断言 `onChange → setAnswer` 绑定存在，防止"填了不算"。
2. **真实渲染**（`test/clarify-card.render.test.js` + `devtools/render-clarify-card.mjs`）：用 `vm` 加载 client.js，注入极简 React 兼容层（只用 `createElement/useState/useEffect`）与极简 DOM，跑**真实渲染代码**（DrawerBody → TaskCard → 澄清卡片），通过点击 tab / 展开卡片 / 输入作答框模拟真实交互；再（本机有 Chrome 时）把结果交给 headless Chrome，用 `getComputedStyle` 核对 15px/700、3px 强调竖条、圆角、进度与徽章配色。无 Chrome 时该条自动跳过。
