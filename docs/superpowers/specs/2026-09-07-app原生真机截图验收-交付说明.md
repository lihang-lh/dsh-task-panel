## 1. 实现逻辑说明

改动目标：把面板「验收截图」能力从 web 扩展到原生 App——当任务是 iOS/Android 工程时，开发/复核代理在开发者本机用系统工具（adb / xcrun simctl / idb）截取真机/模拟器实际运行界面，产物走**现有**截图收集/下发/展示管道；缺工具/无设备/未配对时任务停留在「开发中」，面板卡片显示「待接设备」徽标与**按平台的安装/连接指引**，老板接好设备后点「重新执行」重试。状态机、web/纯后端行为零改动。

核心数据流：

```
成功：开发代理（探测平台 → 探测工具/设备 → 构建启动 app → 按平台命令截屏 → PNG 进 screenshots 目录）
      → 上报 screenshots[] → host collectScreenshots 拷贝 → /files 下发 → 面板展示（与 web 截图一致）

受阻：开发代理 done=false + deviceStatus{ok:false, platform, missing[], detail}
      → host runDevelop 调 deviceGuidance() 生成分平台指引 → task.flags.deviceGuidance（持久化）
      → 面板「待接设备」徽标 + 指引横幅（仅 develop 状态）
      → 老板装好/接好设备 → 点「重新执行」(rerun) → runDevelop 重跑，开头清旧标记
```

## 5. E2E 验证与限制

本仓库无 Android/iOS 工程与真机；改动可分两层验证：

1. **已自动验证**：host 侧纯函数与 prompt（单测 + grep 核对）、client 渲染结构（review 子代理静态审查 + `node --check`）。
2. **需人工/真机验证（按 README §3 与 Q3）**：
   - client UI 无法在无 DSH 环境独立渲染（client.js 依赖 `window.__DSH_BOOT__` 与 Host HTTP API），请在 dsh web 中人工核对：发布一个 app 任务（或构造受阻场景）→ 卡片应出现橙色「待接设备」徽标与展开指引横幅；web 任务回归不受影响。
   - 真实 app 任务（需本机装 Xcode/adb 并连真机）：发布 Android/iOS 工程 UI 改动任务 → 开发代理应自动截真机屏入「验收截图」区；拔掉设备发布同类任务 → 出现徽标与指引 → 接好设备点「重新执行」重试成功。
