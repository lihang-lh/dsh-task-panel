## 1. 需求与背景

老板反馈：**面板里「待澄清问题」区域文字太小，看不清，希望改成卡片形式、醒目一些。**

改造前的实现（`client.js` 旧版 799–807 行）：整块澄清区是一个 `.tp-sec`（12px）文本块，问题正文用 `.tp-kv`（12px）以 `Q1. 问题（why）` 一行挤在一起，作答框 13px，多个问题之间只有 8px 间距——没有边框、没有底色、没有主次，与「需求/验收标准/计划」等段落视觉同级，看不出「这是需要我回答的东西」。

另外两处信息缺失：

1. 展开态看不出**答了几问**，提交前无法确认是否漏答；
2. 收起态的卡片徽章（`cardBadge()`）只覆盖 `review / done / develop`，**`clarify` 状态没有徽章**——任务停在待澄清时，收起卡片就完全看不到有事等着处理。

## 2. 已确认的设计决策（老板逐条拍板）

| # | 决策 |
| --- | --- |
| R1 | 范围：只改 `dsh-task-panel` 任务卡片展开后的「待澄清问题」区域 |
| R2 | 形态：**每问一张独立强调色卡片**（左侧强调竖条 + 浅强调底色 + 圆角），不做整块大卡、不做折叠 |
| R3 | 字号：问题正文 **15px 加粗**；`why` 说明 12px 次级灰；作答框 14px |
| R4 | 新增 **「已答 x/y」** 进度提示（全部答完转绿） |
| R5 | **收起态**也显示「待澄清 N 问」徽章 |
| R6 | 面板其余部分的字号与视觉**不动** |

## 3. 实现逻辑说明

### 3.1 数据流（零改动）

```
Host tasks-list → toSummary() → questions[{id,q,why,answer}]
                                    ↓
客户端 store.tasks → TaskCard(展开) → 澄清卡片区
                                    ↓
       answers 草稿（组件内 useState）→ clarifyProgress() 计算进度与已答集合
                                    ↓
       作答框 onChange → setAnswer → 提交时 submitAnswers()（口径一致）
```

**核心取舍：不改 Host 一行代码、不改 tasks.json 结构、不改 `clarify-answer` 协议**——纯渲染层改造，风险面最小。

### 3.2 新增纯函数 `clarifyProgress(questions, answers)`

```js
// 答案优先级与 submitAnswers() 完全一致：草稿 answers[qid] 优先于已有答案 q.answer；
// 已答口径 = trim 后非空（纯空白不算已答）。
function clarifyProgress(questions, answers) { ... }
// → { answered, total, answeredIds }
```

放在 `client.js` 里（`cardBadge` 附近），进度提示与已答卡片高亮**共用同一份判定**，避免"进度显示已答、提交却没上报"这类口径分叉。

### 3.3 卡片结构（每问一张）

```
┌─ 待澄清问题（至少回答一个，其余按未回答处理）        已答 2/3 ─┐
│ ┌────────────────────────────────────────────────────────┐ │
│ ┃ [Q1]  本次首页改版的范围是仅移动端，还是移动端 + PC 端一起改？  │  ← 15px 加粗 + 实心蓝胶囊
│ ┃       影响工作量与联调排期，范围不同工期差一倍              │  ← why，12px 灰
│ ┃       [ 你的回答…                                      ]  │  ← 14px 作答框
│ └────────────────────────────────────────────────────────┘ │
│ ┌ 已答卡片：边框/竖条/底/序号胶囊整体转绿 ─────────────────┐ │
└──────────────────────────────────────────────────────────┘
```

关键实现点：

- **序号用渲染索引 `i + 1`**（原来用 `q.id.slice(1)`，假设 id 形如 `q1`；索引是渲染期唯一可靠来源，Host 的 `pickQuestions` 生成顺序即展示顺序）。
- **`why` 不再拼进问题正文**（原来是 `q.q + "（" + q.why + "）"`），拆成独立次级行——长 `why` 不会再把问题正文挤成一坨。
- **已答卡片转绿**：`.tp-q-done` 同时改边框、左侧竖条、底色与序号胶囊（否则会出现「卡片绿、胶囊蓝」的割裂感）。
- **未答/已答判定**：`answeredIds[q.id] === true`，输入或清空作答框即时重算。

### 3.4 收起态徽章

`cardBadge()` 新增 `clarify` 分支（放在既有分支之后、`return null` 之前，既有状态优先级不受影响）：

```js
if (task.status === "clarify") {
  const pending = (task.questions || []).length
  return { cls: "tp-badge-clarify", text: pending > 0 ? "待澄清 " + pending + " 问" : "待澄清" }
}
```

徽章渲染在卡片行（`.tp-card-row`，始终可见），无需展开即可看到。
